# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Stripped-down starter based on Apollo v7.0.0 — PrimeTek's commercial Vue 3 admin template (PrimeVue 4 + Tailwind CSS v4 + Vite 5). Plain JavaScript (`<script setup>`, no TypeScript), `@` → `./src` alias. Demo pages were removed; only Dashboard, Settings, Help and an admin-only example page remain, plus the auth pages. The original template (`original_template/`, git-ignored) is the reference for any removed demo component.

## Commands

Lockfile is `package-lock.json` → npm.

- `npm run dev` — Vite dev server
- `npm run build` / `npm run preview`
- `npm run lint` — ESLint with `--fix` (vue3-essential + prettier + `@intlify/vue-i18n`), also linting the locale JSON files
- `npm run format` — Prettier write (js/vue only). Don't point `prettier --write` at `src/assets/` — vendored Apollo styles, not in `.prettierignore`.

- `npm test` — Vitest (run once); `npm run test:watch` for watch mode
- Single file: `npx vitest run src/stores/__tests__/layout.spec.js`; single test: add `-t "<name>"`

`typescript` is a devDependency pinned to 5.9 even though the code is JavaScript. Several packages ask for TypeScript (filestack-js → ts-node, pinia, vue), and npm would otherwise install TypeScript 7, whose per-platform binary packages were missing from the lockfile and broke `npm ci` in CI. After changing dependencies, check that `npm ci` succeeds in a clean copy.

Vitest is pinned to v3 because v4+/v5 require Vite 6+ (project is on Vite 5). Test environment is jsdom (`test` block in `vite.config.mjs`). Store tests live in `src/stores/__tests__/`: fresh `setActivePinia(createPinia())` and `localStorage.clear()` per test; `@primeuix/themes` is mocked in the layout tests. Don't `structuredClone` store state in tests (reactive proxies can't be cloned). Component tests use Vue Test Utils (`@vue/test-utils`) through `mountWithApp(component, { path, routes, props })` from `src/test/mount.js`. It sets up a fresh Pinia, PrimeVue (no theme) and a memory router at `path`; pass named routes so `RouterLink`s resolve. PrimeVue components resolve through the same auto-import as the app. Put tests in `__tests__/` next to the code, and use `flushPromises()` after a form submit (the Zod resolver is async).

## Conventions

- SFC block order enforced by ESLint: `<script>`, `<template>`, `<style>`.
- Prettier: 4-space indent, single quotes, semicolons, no trailing commas, `printWidth: 250` (long lines are expected).
- PrimeVue components are **auto-imported** via `unplugin-vue-components` + `PrimeVueResolver` (`vite.config.mjs`) — don't add manual `import Button from 'primevue/button'`.
- **VueUse** (`@vueuse/core`): prefer its composables over hand-written listeners, timers, observers and storage, e.g. `useMediaQuery`, `onClickOutside`, `useIntersectionObserver`, `useTimeoutFn`, `useCountdown`, `useNow`, `useStorage`. They clean up after themselves. Import them explicitly (no auto-import), like everything else here. `useNow` defaults to updating every animation frame, so pass a `scheduler` such as `useIntervalFn`.
- `ToastService` and `ConfirmationService` are installed globally; a single `<Toast />` lives in `AppLayout.vue`.

## Architecture

- **Routing** (`src/router/index.js`): one root route renders `layout/AppLayout.vue` with app pages (`/`, `/settings`, `/help`, `/admin`) as lazy-loaded children; `/admin` is the `meta.roles` example. Top-level siblings without the layout: `/auth/*` (login, register, forgot-password, reset-password, verification, access = Access Denied, error), `/terms` (public), and the catch-all, which renders `views/auth/Error.vue` with `notFound` (requires auth, so signed-out users get login instead). `router.onError` sends failed navigations to the error page, which is imported eagerly for that reason. `meta.breadcrumb` (array) drives `AppBreadcrumb`. `meta.search: { icon, keywords, title? }` adds a page to the topbar search. This is a Fuse.js fuzzy search (`src/search/`: `buildPageIndex`/`searchPages` are pure and tested, `usePageSearch` wraps VueUse `useFuse`). The title defaults to the breadcrumb, and pages whose `meta.roles` exclude the user are left out. Give new pages a `search` entry. Sidebar items are a separate model in `layout/AppMenu.vue` (a `computed`, so items can set `visible` from the session, e.g. Admin) — adding a page means updating both router and menu. Hiding a menu item is cosmetic; `meta.roles` is the real check.
- **State (Pinia)** (`src/stores/`): setup stores, each with an HMR snippet. `layout` = `config` (appearance: preset, primary, surface, darkTheme, menuMode, menuTheme; persisted) + `ui` (transient sidebar/menu/drawer flags) + getters (`isSlim`, `hasOverlaySubmenu`, …) and actions (`toggleMenu`, `setMenuMode(mode, path)`, `setPrimary`, `applyTheme`, …). `user` = profile; `preferences` = regional + notifications; `todos` = drawer To-Do list. Persistence uses `usePersistedRef(key, defaults)` from `stores/persisted.js`, built on VueUse `useStorage`: localStorage key `app.<key>`, stored objects shallow-merged over defaults, a wrong-shaped or malformed value is ignored, and storage errors are swallowed. Because it uses `useStorage`, changes in another tab are picked up too, so locking in one tab locks them all — use it for any new state that should survive reloads. Components call `useXStore()` and access fields on the store object (don't destructure without `storeToRefs`). `AppLayout.vue` maps `layout.config`/`layout.ui` to `layout-*` CSS classes. Menu modes: static, overlay, slim, slim-plus, horizontal, reveal, drawer; menu themes: colorScheme, primaryColor, transparent.
- **Auth** (`src/auth/`): Better Auth **client only** — `authClient` from `better-auth/vue` with the `emailOTPClient()` plugin (`client.js`). With no `VITE_AUTH_URL` (see `.env.example`) its `customFetchImpl` is `mock-server.js`, an in-browser stand-in answering the Better Auth endpoints the app uses (core + emailOTP) with their real response shapes: any password and any 6-digit code work, `admin@…` users get `role: 'admin'` (others `user`), users + session live in localStorage (`app.auth.mock`, never passwords), and reset links / verification codes are logged to the console. Setting `VITE_AUTH_URL` switches to a real server (needs `emailAndPassword`, `emailOTP`, `user.deleteUser.enabled`, and the admin plugin if roles are used). `router/guard.js` reads route meta through matched records (children inherit, nearest wins): `requiresAuth` → login with `?redirect=`; `guestOnly` → home; `roles: [...]` → `access-denied` with `?from=`; and while locked, in-app navigation is blocked (the initial navigation is allowed so reloads work). `safeRedirect()` only allows same-app paths. Register → Verification (email OTP) → redirect. Use `useSignOut()` (`auth/useSignOut.js`) for sign-out — it also clears the lock. Auth pages use `components/auth/AuthLayout.vue` (Apollo wave + card); Error/Access use `components/auth/StatusPage.vue`. Zod schemas in `auth/schemas.js` (password rules shared with `views/settings/password-schema.js`). The profile in the `user` store is still local (seeded on sign-up), separate from the auth user. In Zod 4 avoid `z.literal()` for fields in a schema with a cross-field `.superRefine()` — a literal mismatch aborts and skips the refinement; use `.refine()`.
- **Lock screen** (`stores/lock.js` + `layout/AppLockScreen.vue`, mounted in `App.vue`): an overlay rather than a route, so the page underneath keeps its state (e.g. a half-filled form); the app is `inert` while it shows. Lock state persists across reloads. Unlock re-runs `signIn.email` with the session user's email, because Better Auth's `/verify-password` is server-only. Lock button: topbar (next to the avatar).
- **File uploads (Filestack)** (`src/service/filestack.js`): `filestack-js` is loaded with a dynamic `import()` on first use, so it gets its own chunk (~580 kB). The key comes from `VITE_FILESTACK_API_KEY` and falls back to Filestack's shared demo key (`isDemoFilestackKey`); don't hardcode a real key. The demo key's upload API can be blocked (`429 {"blocked":true}`), so test real uploads with your own key, with localhost added to its allowed origins. `openAvatarPicker` gives one image with a forced square crop; `avatarUrl(handle)` builds the CDN transform URL (resize before output). Settings > Profile > Photo saves that URL to the auth user's `image` right away (not on form Save). `useAvatar()` (`auth/useAvatar.js`) gives the topbar its image, falling back to the placeholder; the lock screen uses `user.image`. The picker's default upload retries take minutes, so `uploadConfig.retry` is kept low and `onFileUploadFailed` closes the picker so the page can show an error.
- **Feature flags (Flagsmith)** (`src/flags/index.js`, via `flagsmith-vue`): `installFlags(app)` in `main.js` starts the SDK and provides it, and components read flags with `useFlags(['name'])` from `flagsmith-vue` (`flag?.enabled`, `flag?.value`). Every flag must be listed in `DEFAULT_FLAGS` with its offline/initial value. These defaults are published right away, because the SDK only emits flags after a fetch. Without `VITE_FLAGSMITH_ENVIRONMENT_ID` nothing is fetched (`preventFetch`). `App.vue` calls `identifyFlagsUser` when the session user changes, sending id + `role` as a trait, or logs out of Flagsmith on sign-out. Example flag: `profile_photo_upload` (gates Settings > Profile > Photo).
- **i18n (vue-i18n 11, Composition API)** (`src/i18n/`): every user-facing string goes through vue-i18n — `$t('key')` in templates, `const { t } = useI18n()` in `<script setup>` (toasts, option lists in a `computed` so they follow the language), `<i18n-t keypath scope="global">` when a sentence contains markup (links, `<strong>`, `<code>`). ESLint enforces it (`@intlify/eslint-plugin-vue-i18n` v3, the last version for ESLint 8 / `.eslintrc`): `no-raw-text` flags hard-coded text and common text attributes (`label`, `placeholder`, `header`, `aria-label`, …) in templates — it doesn't look inside `<script>`, so check toasts and option arrays yourself; `no-missing-keys` and `no-unused-keys` check keys against `locales/en.json`. Keys referenced indirectly are exempt from the unused check: `nav.*` (route meta, menus), `validation.*` (Zod schemas) and `auth.errors.*` (by error code); `i18n.spec.js` checks the schema keys exist instead. Prefer literal `t('a.b')` calls over building keys from strings so the linter can follow them. Code samples and user data (product names, to-dos) aren't translated; put them in script constants. Messages live in `locales/{en,es,fr,de}.json` (camelCase keys, enforced); when adding a key, add it to all four (`i18n.spec.js` fails otherwise). vue-i18n message syntax treats `{ } @ $ |` as special, so pass emails and code as `{params}`. English is bundled and is the fallback; the other languages load on demand through `setLocale(code)`, which also loads PrimeVue's own texts from `primelocale` (date picker, paginator, aria labels; applied by `syncPrimeVueLocale(app)` in `main.js`) and sets `<html lang>`. `installI18n(app)` follows `preferences.regional.language` (Settings > Preferences); the app mounts once the saved language has loaded. Validation: Zod schemas use message keys (`validation.*`) and forms show them with `components/forms/FieldError.vue` (`<FieldError id="x-error" :field="$form.x" />`, `show` to override when it appears), which translates and passes `{min}`. Better Auth errors go through `authErrorMessage(error, t('…failed'))` (`auth/errors.js`), which maps `error.code` to `auth.errors.<camelCaseCode>` — add codes there as the server uses them. Numbers: `$n(value, 'currency')` / `'currencyWhole'` (named formats in `i18n/index.js`); dates use `Intl` with `locale.value`; charts watch `locale` to rebuild labels. The phone picker localises country names with `Intl.DisplayNames`, and the Filestack picker gets `lang`. Route `meta.breadcrumb` and `meta.search.title` hold message keys. The es/fr/de texts are drafts written by Claude; have a native speaker review them. `@intlify/unplugin-vue-i18n` needs Vite 6+, so messages are plain JSON imports.
- **Translation platform (Tolgee)**: the locale JSON files are the source of truth in git. Tolgee (project "Apollo Template", app.tolgee.io) is where they get machine-translated and reviewed, with vue-i18n still the runtime; the `@tolgee/vue` SDK is deliberately not used. `npm run i18n:push` uploads `locales/*.json` (`.tolgeerc.json`: `JSON_ICU` format, `forceMode: KEEP`, so it only adds keys and never overwrites platform edits). `npm run i18n:pull` downloads every language file and runs Prettier on them; Tolgee sorts keys alphabetically. Commit the pulled files after review. `scripts/tolgee.mjs` passes `VITE_APP_TOLGEE_API_URL`/`VITE_APP_TOLGEE_API_KEY` from `.env` to the CLI. In `npm run dev`, with the key set, `src/i18n/tolgee.js` adds in-context editing (hold Alt and click a text). `connectTolgee` tags each vue-i18n string with its key through `setPostTranslationHandler` + `tolgee.wrap`. It also merges platform translations (loaded at start or saved in the editor) over the bundled messages for languages vue-i18n has loaded, and follows the locale. `installI18n` loads it only when `import.meta.env.DEV` and the mode isn't `test`, so builds contain neither Tolgee nor the key (check `dist/` if this changes). Don't compare translated strings in code: in dev they carry invisible marker characters. Tolgee uses ICU syntax for plurals; vue-i18n's pipe plurals (`today.events`) show as plain text there. Add new languages in the Tolgee UI first, because the project API key can't create them. Production also reads Tolgee's Content Delivery (CDN): with `VITE_TOLGEE_CDN_URL` set (public, no key; set it in Vercel), `setLocale` calls `loadPublished(code)` in the background for the language and its base. It fetches `<url>/<code>.json` (flat keys, converted by `toMessages` in `i18n/messages.js`) once per session and merges it over the bundled messages. A 404 (nothing published yet) or a network error leaves the bundled texts. It's off in development, where `tolgee.js` covers this live. So publishing in Tolgee updates production without a deploy. Still `npm run i18n:pull` before releases, so git and the bundle stay current. Keep `toMessages` out of `tolgee.js`: production code imports it, and `tolgee.js` must not end up in the bundle.
- **Theming**: presets (Aura/Lara/Nora) and primary/surface palettes live in `src/layout/theme.js`. Presets are lazy-loaded with `loadPreset(name)` (unknown names fall back to Aura), so only the active one is in the startup download. `main.js` waits for it before mounting, and `applyTheme()`/`setPreset()` are async; theme changes go through `layout` store actions (`@primeuix/themes` `$t` / `updatePreset` / `updateSurfacePalette`). `main.js` installs Pinia first, loads the saved preset, boots PrimeVue with it, then awaits `layout.applyTheme()` to restore colors and dark mode. `layout/AppConfig.vue` is the inline Appearance panel (rendered in Settings > Appearance). Dark mode = `app-dark` class on `<html>` (matches `darkModeSelector` and the Tailwind `dark` custom variant in `assets/tailwind.css`).
- **Styling**: `src/assets/` holds the Apollo styles (originally the private `primefaces/apollo-assets` submodule, now committed as plain files). Layout SCSS lives in `assets/layout/` (split by sidebar mode, menu theme, light/dark variables; page padding in `_content.scss`, max content width `$content-max-width` (1730px) in `_sass_variables.scss`), entry `assets/styles.scss` uses `@use`. Tailwind v4 is configured CSS-first in `assets/tailwind.css` (custom breakpoints sm 576 / md 768 / lg 992 / xl 1200 / 2xl 1920 + `tailwindcss-primeui` plugin); `tailwind.config.js` is a v3 leftover.
- **Utility drawer** (`src/layout/AppProfileSidebar.vue`, toggled by the topbar avatar via `layout.toggleProfileSidebar()`): To-Do list from the `todos` store and today's schedule (placeholder events generated for today).
- **Data**: no backend (auth is mocked, see Auth). `src/service/ProductService.js` returns hardcoded mock data (used by dashboard widgets); user/preferences data is only in Pinia + localStorage; Account section talks to the (mock) auth client. Images used by kept pages live in `public/demo/images/{avatar,product}`.
- **Settings** (`views/settings/`): `SettingsLayout.vue` (left nav, tab strip below `lg`) + one child route per section (`/settings/<section>`, `/settings` redirects to profile). Sections are built from `components/settings/SettingsSection.vue` (header + actions slot) and `SettingsRow.vue` (label/description + control). The Profile phone field uses `components/forms/PhoneInput.vue`, a wrapper around vue-tel-input styled with PrimeVue's global `--p-form-field-*` / `--p-overlay-select-*` tokens; component tokens like `--p-select-*` only exist when that component is on the page. Its v-model is E.164 (`+14155550123`) and it is imported locally, not installed globally. It's bound with `<FormField v-slot="$field" name="phone">` + `$field.onInput({ value })` and validated with libphonenumber-js `isValidPhoneNumber`. Profile uses PrimeVue Forms (`<Form>` with `name`-bound inputs, `novalidate`) + Zod 4 via `zodResolver(profileSchema)` (`views/settings/profile-schema.js`; email optional but must be valid; validates on blur and submit). The resolver submits the schema's parsed output and `z.object()` strips unknown keys, so every form field must be in the schema. Account's change-password form (`password-schema.js`: current required, new ≥ 8 chars, confirm must match via `.superRefine()` with `path: ['confirmPassword']`) validates on mount and on every keystroke so the submit button can use `:disabled="!$form.valid"`; fields pass `:invalid` explicitly so errors only show once a field is dirty (an explicit `invalid` prop overrides the form's state). Passwords are never stored. Preferences edits a draft; Profile and Preferences commit to their store on Save. Notifications/Appearance apply immediately. Keep `@primevue/forms` on the same version as `primevue` (latest `@primevue/forms` is v5, for PrimeVue 5). `AppMenuItem` keeps leaf items highlighted on nested routes.
- **Views**: top-level pages in `src/views/*.vue`. `Dashboard.vue` composes widgets from `components/dashboard-widgets/` (Chart.js charts via PrimeVue `Chart`).

## CI

`.github/workflows/ci.yml` runs on pull requests only (opened/synchronize/reopened): three parallel jobs — **Lint** (`npm run lint:check`, the non-fixing variant of `npm run lint`), **Unit tests** (`npm test`) and **Build** (`npm run build`) — each doing `npm ci` with Node from `.nvmrc`. Keep `.nvmrc` in sync when changing Node versions, and keep job `name:`s stable (they are the status-check names).

## Deployment

Vercel (`vercel.json`): SPA rewrite to `/index.html`; build is `npm run build` (no `GITHUB_ACCESS_TOKEN` needed).
